## ✨ 特性

- 🎯 **纯 HTML Fragment** — 不依赖任何框架，复制即用

## 🚀 快速开始

### npm 安装

```bash
npm install @itkdm/open-lab-components
```

```js
const lab = require('@itkdm/open-lab-components');

const all = lab.list();                                    // 全部 210 个组件
const circuit = lab.list({ category: 'physics/circuit' }, { locale: 'en' });
const battery = lab.get('phy.power.battery.basic', { locale: 'en-US' });
const categories = lab.categories();
const html = lab.readSync('phy.mechanics.projectile.interactive'); // 读取 HTML
```

### 直接使用 HTML

从 `components/` 目录复制组件文件，粘贴到你的页面中，通过 CSS 变量配置参数：

```html
<div class="cmp" data-cmp-id="phy.resistor.axial.basic"
     style="--cmp-size: 80px; --cmp-body: #caa070;">
    <!-- 组件内容 -->
</div>
```

### 本地开发

```bash
git clone https://github.com/itkdm/open-lab-components.git
cd open-lab-components && npm install
npm run dev:site      # 启动开发服务器
npm run validate      # 验证组件规范
npm run build         # 构建全部
```

## Localization

Open Lab Components now ships locale-aware metadata across the component registry, site, MCP server, and JS API.

- Default locale: `zh-CN`
- Current locales: `zh-CN`, `en`
- Raw multi-locale registry: `registry/registry.json`
- Localized registry views:
  - `registry/registry.zh-CN.json`
  - `registry/registry.en.json`
- JS API:
  - `lab.list(filter, { locale: 'en' })`
  - `lab.get(id, { locale: 'en' })`
- MCP tools:
  - `get_categories({ locale })`
  - `list_components({ ..., locale })`
  - `search_components({ ..., locale })`
  - `get_component({ id, locale })`

Legacy `cmp-manifest/v1` components remain supported during migration. New bilingual samples use `cmp-manifest/v2`.

See [release notes](./docs/RELEASE-2026-03-I18N.md) for the migration summary, output changes, and consumer guidance.

发布前检查和发版步骤见 [PUBLISHING.md](./docs/PUBLISHING.md)、[RELEASE-CHECKLIST-0.2.0.md](./docs/RELEASE-CHECKLIST-0.2.0.md)、[GITHUB-RELEASE-0.2.0.md](./docs/GITHUB-RELEASE-0.2.0.md)。
中文对外公告可直接参考 [ANNOUNCEMENT-0.2.0.zh-CN.md](./docs/ANNOUNCEMENT-0.2.0.zh-CN.md)。
## Repository checks

Use these root entrypoints before release-facing changes:

- `npm run build:registry`
- `npm run check:root`
- `npm run check:generated`
- `npm run check:release`

Generated outputs stay on explicit boundaries:

- `registry/registry.json` and other `registry/*.json` files are generated from `components/`
- `site/dist/` is generated by `npm run build:site`
